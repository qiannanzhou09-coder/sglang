CPU 机可以帮你把“环境装好”，但不能替代 GPU 启动验证。
  因为你最终跑的是 CUDA + sglang-kernel + 多卡 TP 路线，真正会不会成功，还是要在 GPU 上过一次最小启动测试。

  所以最合理的流程不是“CPU 全验证完再上 GPU”，而是：

  1. CPU 机做镜像
  2. GPU 机用一个 1B 小模型做 smoke test
  3. 小模型能起，再换 122B 和完整参数

  这样不会白搞，而且成本最低。

  你现在最该做的方案

  第一步：CPU 机做镜像，但只要求“环境对齐”
  目标不是在 CPU 上把 122B 跑起来，而是确保镜像里这些版本一致：

  - torch
  - sglang
  - sglang-kernel
  - flashinfer
  - 其他老师 requirement 里的包

  CPU 机可以做这些验证：

  python3 - <<'PY'
  import torch, sglang, importlib.metadata as m
  print("torch:", torch.__version__)
  print("sglang:", sglang.__version__)
  print("sglang-kernel:", m.version("sglang-kernel"))
  PY

  再跑环境检查：

  python3 -m sglang.check_env

  这一步只能证明：

  - 包装对了
  - import 通了
  - 镜像没明显坏

  它不能证明 CUDA server 一定能起。

  第二步：GPU 机用 1B 模型做最小启动测试
  这是关键步骤，也是你避免“白搞”的办法。

  建议你先下一个小模型，比如：

  - Qwen/Qwen2.5-1.5B-Instruct
  - 或更小的 Qwen/Qwen2.5-0.5B-Instruct

  然后在 GPU 机启动最小命令，不要一上来就带长上下文、投机解码、复杂 parser。

  先用这种最小版：

  cd /inspire/qb-ilm2/project/26summer-camp-18/26230029/sglang

  export HF_HUB_OFFLINE=1
  export TRANSFORMERS_OFFLINE=1

  python3 -m sglang.launch_server \
    --model-path /inspire/qb-ilm2/project/26summer-camp-18/26230029/models/Qwen2.5-1.5B-Instruct \
    --host 0.0.0.0 \
    --port 8000 \
    --tp-size 1

  如果你还想顺带验证多卡 TP/NCCL，再跑：

  python3 -m sglang.launch_server \
    --model-path /inspire/qb-ilm2/project/26summer-camp-18/26230029/models/Qwen2.5-1.5B-Instruct \
    --host 0.0.0.0 \
    --port 8000 \
    --tp-size 8

  这样你验证的是：

  - torch 和 CUDA 是否匹配
  - sglang-kernel 能不能真正加载
  - server 能不能起来
  - 多卡通讯有没有问题

  第三步：小模型通过，再切 122B
  等 1B / 1.5B 小模型能稳定起来，再换成你的大模型路径，再逐步加参数：

  1. 先只换模型路径
  2. 再加 --tp-size 8
  3. 再加长上下文
  4. 最后再加 speculative decoding / parser / cache 参数

  不要一口气把所有复杂参数全加上，不然出问题时很难定位。

  为什么这套流程最好
  因为你现在真正需要的是两种验证：

  - CPU 机
      - 验证镜像构建没问题
      - 依赖版本没乱
  - GPU 机
      - 验证 CUDA 运行时真的能起
      - 验证 sglang-kernel 和 GPU/torch ABI 匹配

  这两者缺一不可。

  我的建议结论

  - 是，先在 CPU 做镜像是对的
  - 但 CPU 不需要也不应该去启动 122B server
  - 真正的“避免白搞”方法是：GPU 上先用 1B 小模型 smoke test

就你现在“尽快把 CPU 侧环境做对、然后上 GPU 跑起来”的目标，这一步是对的。

  但有一个关键补充：

  requirements_sglang.txt 装完后，不要马上起 server。先补一遍 cu130 的 sglang-kernel wheel。

  因为你这台目标 GPU 机器是 CUDA 13.0，而老师的 requirements_sglang.txt 里只是：

  sglang-kernel==0.4.0

  这不一定会自动变成你要的 +cu130 版本。你前面已经踩过一次这个坑了。

  最省事的流程

  1. 先等这条命令跑完：

  python3 -m pip install -r requirements_sglang.txt

  2. 跑完以后，立刻强制安装 cu130 的 kernel wheel：

  python3 -m pip install --force-reinstall --no-deps \
  "https://github.com/sgl-project/whl/releases/download/v0.4.0/sglang_kernel-0.4.0+cu130-cp310-abi3-manylinux2014_x86_64.whl"

  如果你的机器不是 x86_64，再换成 aarch64 版本。

  3. 然后检查环境：

  python3 - <<'PY'
  import torch, importlib.metadata as m
  print("torch:", torch.__version__, "cuda:", torch.version.cuda)
  for pkg in ["sglang", "sglang-kernel", "transformers", "flashinfer-python", "flashinfer-cubin"]:
      try:
          print(pkg, m.version(pkg))
      except Exception as e:
          print(pkg, "MISSING", e)
  PY

  你希望看到的核心是：

  - torch: 2.9.1
  - cuda: 13.0
  - sglang: 0.5.10rc0
  - sglang-kernel: 0.4.0

  4. 再跑环境检查：

  python3 -m sglang.check_env

  现在最重要的建议

  - 先不要 pip install -e 你的本地源码
  - 先不要切回 main
  - 先把老师这套环境完整跑通并做成镜像

  因为你现在的目标不是开发最新代码，而是先把服务拉起来。
  等 GPU 上用 1B 小模型 smoke test 成功，再决定要不要把你的代码以 editable 方式挂进去。

  接下来应该怎么验证

  CPU 机这边做完后：

  - 不要求把 122B server 在 CPU 上跑起来
  - 只要求环境版本一致、镜像能构建

  真正的启动验证放到 GPU 机，用 1B 小模型，比如：

  - Qwen/Qwen2.5-0.5B-Instruct
  - Qwen/Qwen2.5-1.5B-Instruct

  如果你愿意，等你这条 pip install -r 跑完后，把输出最后几十行发我，我直接告诉你下一条该执行什么。
