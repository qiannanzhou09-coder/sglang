# 个人成果贡献报告

## 一、个人负责内容概述

本次实训中，我主要负责 SGLang 长会话推理服务优化相关工作，包括实验方案设计、并行策略对比、参数调优、cache 问题分析、准入控制实现与验证、模型剪枝/量化方案规划等。整体目标是提升多 session、多轮长会话 workload 下的推理吞吐、cache 命中率和服务稳定性。

## 二、主要个人贡献

### 1. 设计并搭建测试基线

- 设计了 `T1_sysprompt_pure` 和 `T6_official_50` 两类测试集：
  - `T1` 用于观察 prefix cache 和 router 是否正常；
  - `T6` 用于接近官方分布的小规模性能对比。
- 使用纯 TP8 方案建立 baseline：
  - T1：`cache_hit_rate=97.95%`，`output_throughput=799.7 tok/s`；
  - T6：`avg_session_time=165.65s`，`cache_hit_rate=96.72%`，`output_throughput=596.8 tok/s`。
- 该 baseline 为后续所有优化方案提供了稳定对照。

### 2. 完成并行策略探索

- 测试了 `TP8`、`DPA TP8 DP8`、`DPA TP8 DP2`、`DPA TP8 DP4` 等多种并行配置。
- 发现 `DP8 + cache-aware router` 虽然 cache hit 较高，但会导致单个 DP rank 负载过重，整体吞吐下降。
- 通过 no-router 对照实验确认：DPA 本身不是唯一问题，router 的 cache locality 策略和负载均衡存在冲突。
- 最终阶段性选择 `TP8 + DP2 DPA + cache-aware router` 作为更稳定的并行方案。

### 3. 完成参数调优与问题定位

- 调整了 `CHUNKED_PREFILL_SIZE`、`SCHEDULE_CONSERVATIVENESS` 等调度参数，使 DPA 默认表现有所改善。
- 定位到投机解码会影响默认最大运行请求数，因此统一关闭 `SPECULATIVE_ALGO=NONE`，保证实验结果可比。
- 测试 `MAX_RUNNING_REQUESTS=640`，发现其能提升前期吞吐，但会导致后期 KV cache 压力过大、cache hit 下降。
- 调整 `MEM_FRACTION_STATIC`，确认 `0.92` 比 `0.9` 更合适，而 `0.95` 会触发 OOM。

### 4. 启用并验证 HiCache

- 尝试启用 HiCache 缓解长会话场景下的 KV cache 压力。
- 使用配置包括：
  - `ENABLE_HICACHE=1`
  - `HICACHE_RATIO=2`
  - `HICACHE_IO_BACKEND=kernel`
  - `HICACHE_STORAGE_PREFETCH_POLICY=wait_complete`
  - `HICACHE_WRITE_POLICY=write_through`
- 在实验过程中定位并分析了 HiCache 触发的 SGLang FlashInfer shape mismatch 问题。
- 修复后 HiCache 可以正常运行，为完整 workload 长时间稳定运行提供支持。

### 5. 设计并验证准入控制方案

- 在完整 workload 中发现中后期 cache hit 坍塌、TTFT p99 暴涨、输出吞吐下降的问题。
- 分析判断根因是同时活跃 session 过多，导致 KV working set 超过 cache 容量，大量请求重新 prefill。
- 设计并测试 `MAX_ACTIVE_SESSIONS=64` 的 session 级准入控制。
- 实验结果表明：
  - cache 命中率后期保持更稳定；
  - output token throughput 曲线更平坦；
  - 相比 request-level in-flight 限制，session 级控制更贴近长会话 workload 的真实瓶颈。
- 后续进一步规划 dynamic admission，根据 cache hit、KV usage、TTFT 等指标动态调节并发。

### 6. 完成模型剪枝与量化方向探索

- 参考 REAP 论文，对 MoE expert 剪枝方案进行调研和接入。
- 使用 `PRUNE_MODE=reap_text_only` 生成剪枝后的 text-only 模型。
- 剪枝后显存占用从约 `119GB` 降到约 `96GB`，说明模型层压缩对显存优化有效。
- 同时规划了 KV FP8、剪枝模型 + KV FP8 等后续实验，用于进一步降低 KV cache 和模型显存占用。

### 7. 整理实验脚本与 benchmark 方案

- 整理了不同 serving 方案的启动脚本和 client 脚本。
- 规划了后续 benchmark 组合，包括：
  - DP2 + HiCache；
  - DP8 + HiCache；
  - DP2/DP8 + 准入控制；
  - 剪枝模型；
  - KV FP8；
  - 剪枝模型 + KV FP8。
- 形成了可复现实验流程，方便后续继续补充完整 workload 和精度测试。

## 三、个人成果总结

通过本次实训，我完成了从 baseline 建立、并行策略探索、性能瓶颈分析、参数调优、cache 稳定性优化、准入控制设计到模型剪枝规划的一整套优化工作。主要成果包括：

- 明确了 TP8 baseline 的性能上限和稳定性表现；
- 发现并解释了 DP8 cache-aware router 负载倾斜问题；
- 确定 DP2 DPA 是更适合当前 workload 的并行方向；
- 证明单纯提高并发只能带来短期收益，长期会造成 KV cache 坍塌；
- 验证 HiCache 和 session 级准入控制对长会话稳定性有效；
- 完成 REAP text-only 剪枝模型接入，显存从约 `119GB` 降到约 `96GB`；
- 为后续 KV FP8、动态准入控制和完整 benchmark 对比打下基础。
